## User Scenarios & Testing *(mandatory)*

### User Story 1 - Prompt Version 자동 생성 및 이력 조회 (Priority: P1) 🎯 MVP

프롬프트를 관리하는 사용자 및 시스템은 프롬프트의 템플릿 텍스트나 핵심 내용이 변경될 때마다 기존 버전을 훼손하지 않고 불변(Immutable) 스냅샷으로 보존하며, 1씩 증가하는 버전 번호(v1, v2...)를 가진 신규 버전을 자동 생성하고 전체 이력을 조회할 수 있어야 한다.

**Why this priority**: 프롬프트의 변경 이력을 불변 스냅샷으로 저장하고 목록/상세 조회를 제공하는 것이 버전 관리 시스템의 가장 핵심적인 기초(MVP)이므로 최우선 순위를 가진다.

**Independent Test**: 특정 프롬프트의 템플릿 텍스트를 업데이트했을 때 신규 버전 스냅샷 레코드가 자동 생성되는지 확인하고, 버전 이력 목록 및 상세 조회 API를 호출하여 생성된 버전 데이터가 올바르게 반환되는지 독립 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 프롬프트가 새로 생성되었을 때, **When** 첫번째 템플릿 내용이 입력되면, **Then** 버전 번호 1(`version_number=1`)을 가진 초기 Version 스냅샷 레코드가 자동 저장된다.
2. **Given** 기존 프롬프트에 버전 1이 존재할 때, **When** 프롬프트의 템플릿 내용을 변경하고 저장 요청을 보내면, **Then** 버전 1은 유지된 채 버전 2 (`version_number=2`)의 신규 Version 레코드가 생성되어 반환된다.
3. **Given** 특정 프롬프트에 여러 버전(v1, v2)이 존재할 때, **When** 해당 프롬프트의 버전 목록 조회를 요청하면, **Then** 버전 번호 역순(최신순)으로 정렬된 버전 스냅샷 목록이 반환된다.
4. **Given** 특정 프롬프트 식별자와 버전 번호가 주어졌을 때, **When** 특정 버전 상세 조회를 요청하면, **Then** 해당 버전 시점의 템플릿 텍스트, 변경 기록(changelog), 생성일시가 반환된다.

---

### User Story 2 - 이전 버전으로의 롤백(Rollback) 기능 (Priority: P2)

프롬프트 관리자는 최근 수정된 템플릿에 문제가 발생하거나 이전 버전의 프롬프트로 원복해야 할 때, 과거 특정 버전(예: v1)의 템플릿 스냅샷 데이터를 기반으로 신규 버전(예: v3)을 발행하여 안전하게 롤백을 수행할 수 있어야 한다.

**Why this priority**: 과거 이력을 훼손하지 않고 이전의 검증된 프롬프트 상태로 안전하게 복원하는 롤백 기능은 프로덕션 운영 안정성을 확보하기 위해 필수적인 우선순위를 갖는다.

**Independent Test**: 버전 1과 버전 2가 존재하는 프롬프트에서 버전 1으로의 롤백 API를 호출했을 때, 과거 이력을 삭제하는 대신 버전 1의 내용과 동일한 신규 버전 3이 생성되고 성공 응답이 반환되는지 독립 검증한다.

**Acceptance Scenarios**:

1. **Given** 버전 1과 버전 2가 존재하는 프롬프트가 있을 때, **When** 버전 1 번호를 지정하여 롤백 API를 호출하면, **Then** 기존 v1과 v2 데이터는 변경 없이 보존되고, v1의 템플릿 내용을 복사한 버전 3(`version_number=3`, changelog="Rolled back to v1") 레코드가 신규 등록된다.
2. **Given** 롤백 처리가 성공적으로 완료된 후, **When** 프롬프트의 최신 버전을 조회하면, **Then** 새로 생성된 롤백 버전(v3)이 최신 버전으로 반환된다.

---

### User Story 3 - 버전 간 차이점(Diff) 비교 API 및 테스트 검증 (Priority: P3)

프롬프트 관리자는 두 개 버전 간의 템플릿 텍스트 차이점(Diff)을 한눈에 확인할 수 있는 비교 API를 통해 변경 사항을 사전에 검토할 수 있어야 하며, 전체 버전 CRUD 및 롤백/비교 기능에 대한 유닛 테스트 세트가 100% 통과되어야 한다.

**Why this priority**: 버전 간 변경 내역을 명확히 비교 파악할 수 있도록 돕고, 자동화 테스트로 이력 관리 시스템의 신뢰성을 증명하기 위함이다.

**Independent Test**: 비교 대상 두 버전(예: v1과 v2)의 번호를 인자로 하여 비교 API를 호출하고, 각 라인별 변경점/차이점(Diff) 데이터가 정상 반환되는지 및 자동화 유닛 테스트 세트가 100% 통과하는지 독립 검증한다.

**Acceptance Scenarios**:

1. **Given** 버전 1과 버전 2의 템플릿 텍스트가 다를 때, **When** 두 버전 번호를 지정하여 버전 Diff 비교 API를 요청하면, **Then** 템플릿 텍스트의 추가/삭제/변경 라인 차이점이 명확히 구분된 데이터가 응답된다.
2. **Given** Version CRUD, 이력 조회, 롤백, 비교 API 유닛 테스트 세트가 실행될 때, **When** 테스트 하네스 구동 시, **Then** 모든 케이스가 실패 없이 100% 통과한다.

---

### Edge Cases

- 이미 생성된 기존 `Version` 레코드의 템플릿 텍스트를 직접 수정(PUT/PATCH) 요청 시 405 Method Not Allowed 또는 400 Bad Request 오류를 반환하여 불변성을 보장한다.
- 존재하지 않는 프롬프트 ID나 버전 번호로 조회, 롤백, Diff 비교 요청 시 404 Not Found 오류를 반환한다.
- 이전 버전과 완전히 동일한 텍스트로 프롬프트 업데이트 요청 시, 설정에 따라 신규 버전 생성을 건너뛰거나 변경 없음 메세지와 함께 기존 최신 버전을 유지한다.
- 동일 프롬프트 내에서 동일한 버전 번호(`version_number`)는 고유해야 하며(Unique Constraint), 롤백 시 버전 번호 중복 없이 항상 최신 번호 + 1로 자동 부여되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 프롬프트의 템플릿 내용 변경 시 자동으로 버전 번호를 1씩 증가시키며 신규 `Version` 스냅샷 레코드를 생성해야 한다.
- **FR-002**: 시스템은 생성된 기존 `Version` 레코드를 수정/삭제 불가능한 불변(Immutable) 상태로 보호해야 한다.
- **FR-003**: 시스템은 특정 프롬프트의 전체 버전 이력 목록 조회 및 특정 버전 상세 조회 REST API 엔드포인트를 제공해야 한다.
- **FR-004**: 시스템은 과거 특정 버전 선택 시 해당 버전의 데이터 스냅샷을 복사하여 신규 버전으로 등록하는 롤백 API 엔드포인트를 제공해야 한다.
- **FR-005**: 시스템은 두 버전 간 템플릿 텍스트의 라인별 차이점(Diff) 정보를 반환하는 비교 API 엔드포인트를 제공해야 한다.
- **FR-006**: 시스템은 프롬프트 버전 관리 및 롤백/비교 기능에 대해 자동화된 유닛 테스트 케이스를 구축하고 100% 검증을 통과해야 한다.

### Key Entities

- **Version (프롬프트 버전 스냅샷)**:
  - 특정 시점의 프롬프트 템플릿 텍스트 및 메타데이터를 저장하는 불변 엔티티.
  - 주요 속성: 고유 식별자(ID), 연관 프롬프트 참조(Prompt FK), 순차 버전 번호(Version Number), 템플릿 텍스트(Template Text), 변경 기록(Changelog), 생성일시.
  - 제약조건: (Prompt, Version Number) 복합 고유성(Unique Constraint), 수정 불가(Immutable).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 프롬프트 내용 변경 시 신규 버전 생성 및 이력 스냅샷 저장이 100% 유실 없이 정상 작동한다.
- **SC-002**: 롤백 API 호출 시 기존 변경 이력 훼손 없이 과거 스냅샷 기반의 신규 버전 발행으로 100% 원복된다.
- **SC-003**: 버전 이력 관리 및 롤백/Diff 비교 유닛 테스트 세트 구동 시 100% 성공을 기록한다.
- **SC-004**: 버전 목록 조회, 상세 조회 및 버전 간 Diff 비교 API의 response latency가 1.0초 이내로 즉각 처리된다.

## Assumptions

- 버전에 대한 변경 기록(`changelog`)은 사용자 입력이 없으면 "Version X created" 또는 "Rolled back to Version X" 형태의 자동 메시지가 기록된다.
- 버전 번호는 프롬프트별로 1부터 시작하여 1씩 순차적으로 자동 증가하는 정수형 번호를 사용한다.
- 롤백 동작은 과거 데이터를 덮어쓰거나 롤백 대상 이후 버전을 삭제하지 않고, 과거 버전을 복사하여 최신 번호의 신규 버전을 생성하는 Append-Only 방식을 채택한다.
