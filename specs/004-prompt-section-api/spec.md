## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프롬프트 및 섹션 생성과 관리 (Priority: P1)

시스템 사용자 및 관리자는 서비스에서 활용할 프롬프트(Prompt)와 프롬프트를 구성하는 조각인 섹션(Section)을 신규 등록, 조회, 수정, 삭제(CRUD)할 수 있어야 한다. 이를 통해 프롬프트 자산을 중앙에서 체계적으로 관리하고 업데이트할 수 있다.

**Why this priority**: 프롬프트와 섹션 데이터를 관리할 수 있는 기본 CRUD 기능이 제공되지 않으면 프롬프트 레지스트리로서의 핵심 기능을 수행할 수 없으므로 최우선 순위(P1)를 갖는다.

**Independent Test**: API 인터페이스를 통해 새로운 프롬프트와 연관 섹션을 생성하고, 상세 조회하여 데이터가 일치하는지 확인하며, 수정 및 삭제 후 정상 반영되는지 검증하여 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 등록할 프롬프트 이름, 설명, 업무 분류, 태그 정보가 준비되었을 때, **When** 프롬프트 생성 요청을 보내면, **Then** 고유 식별자를 포함한 생성된 프롬프트 정보가 성공적으로 반환된다.
2. **Given** 기존에 존재하지 않는 프롬프트 ID가 주어졌을 때, **When** 해당 프롬프트 상세 조회를 요청하면, **Then** 대상을 찾을 수 없음을 알리는 리소스 미발견 오류 메시지가 반환된다.
3. **Given** 기존 프롬프트에 속한 섹션 데이터가 존재할 때, **When** 섹션 내용 및 순서를 수정 요청하면, **Then** 변경된 섹션 정보가 프롬프트 상세 조회 시 올바르게 반영되어 조회된다.
4. **Given** 특정 프롬프트를 삭제 요청했을 때, **When** 삭제 처리가 성공하면, **Then** 해당 프롬프트 및 이에 종속된 섹션들이 시스템에서 조회되지 않는다.

### User Story 2 - 이름, 태그, 업무 기반 다차원 검색 (Priority: P2)

프롬프트 관리자 및 외부 애플리케이션은 보유 중인 수많은 프롬프트 중 필요한 대상을 빠르게 찾기 위해 이름(Name) 키워드 검색, 태그(Tag) 필터링, 업무(Task) 구분을 조합한 다차원 검색을 수행할 수 있어야 한다.

**Why this priority**: 등록된 프롬프트 수가 늘어남에 따라 원하는 프롬프트나 특정 업무/태그 범주의 프롬프트 집합을 정확히 찾아내는 기능이 필수적이다.

**Independent Test**: 다양한 태그와 업무 분류를 가진 프롬프트 데이터를 사전 생성한 후, 이름 키워드, 단일/복수 태그, 업무 분류 조건의 다양한 조합으로 검색 API를 호출하여 원하는 대상만 정확히 필터링되는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** '고객상담' 업무(Task)로 분류된 프롬프트들이 존재할 때, **When** 업무 조건으로 '고객상담'을 지정해 검색 요청하면, **Then** 해당 업무로 등록된 프롬프트 목록만 반환된다.
2. **Given** 'summary' 및 'v1' 태그를 동시에 지닌 프롬프트와 'summary' 태그만 지닌 프롬프트가 존재할 때, **When** 'summary' 태그 필터로 검색하면, **Then** 'summary' 태그를 포함하는 모든 프롬프트가 검색 결과에 포함된다.
3. **Given** 이름에 '환불' 키워드가 포함된 프롬프트를 찾고자 할 때, **When** 이름 검색 조건으로 '환불'을 입력하면, **Then** 프롬프트 이름에 '환불'이 들어간 검색 결과 목록을 반환한다.
4. **Given** 업무, 태그, 이름 조건을 동시 지정했을 때, **When** 다차원 검색을 실행하면, **Then** 모든 검색 조건(AND 조건)을 만족하는 프롬프트들만 정밀하게 필터링되어 반환된다.

### User Story 3 - 검색 결과 정렬 및 응답 유닛 테스트 검증 (Priority: P3)

다차원 검색 결과의 가독성을 높이고 시스템 안정성을 보장하기 위해 검색 결과 정렬 기능과 함께 모든 CRUD 및 검색 로직에 대한 검증 유닛 테스트가 제공되어야 한다.

**Why this priority**: 검색 결과의 정렬은 사용자 경험을 개선하며, 유닛 테스트는 향후 기능 확장 및 변경 시 시스템 무결성을 유지하는 안전장치 역할을 한다.

**Independent Test**: 유닛 테스트 실행 도구를 구동하여 CRUD API 엔드포인트 및 다차원 검색 로직에 대해 100% 테스트 케이스가 통과하는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 여러 프롬프트 검색 결과가 존재할 때, **When** 생성일시 역순(최신순) 정렬 조건을 지정하면, **Then** 가장 최근에 생성된 프롬프트부터 순서대로 목록이 반환된다.
2. **Given** 모든 API 엔드포인트 및 다차원 검색 조건 케이스에 대한 유닛 테스트 세트가 준비되었을 때, **When** 테스트 검증을 구동하면, **Then** 모든 테스트 케이스가 실패 없이 정상 통과한다.

---

### Edge Cases

- 프롬프트 신규 생성 또는 수정 시 이미 존재하는 프롬프트 이름(Name)을 입력하면 400 Bad Request 또는 409 Conflict 유효성 오류가 반환된다.
- 존재하지 않는 프롬프트 ID로 섹션을 생성하거나 조회하려는 경우 시스템은 명확한 리소스 부재 오류를 반환한다.
- 태그 검색 조건에 아무런 값이 전달되지 않거나 빈 문자열인 경우, 전체 프롬프트 대상 검색으로 처리되거나 유효성 오류를 명확히 안내한다.
- 동일한 프롬프트 내에 중복된 순서(Order)나 식별 키를 가진 섹션을 등록하려는 경우 적절한 유효성 검사 오류를 반환한다.
- 검색 결과가 존재하지 않을 경우 빈 목록(`[]`)과 함께 정상 응답을 반환한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 프롬프트(Prompt) 신규 등록, 상세 조회, 수정, 삭제를 위한 API 엔드포인트를 제공해야 하며, 프롬프트 이름(Name)의 고유성(Uniqueness)을 검증해야 한다.
- **FR-002**: 시스템은 프롬프트 내 섹션(Section) 등록, 상세 조회, 수정, 삭제를 위한 API 엔드포인트를 제공해야 한다.
- **FR-003**: 시스템은 프롬프트 이름(Name) 키워드 부분 일치 검색 기능을 제공해야 한다.
- **FR-004**: 시스템은 프롬프트에 지정된 태그(Tag) 기반의 필터링 검색 기능을 제공해야 하며, 복수 태그 지정 시 요청된 모든 태그를 포함해야 하는 AND 조건으로 필터링해야 한다.
- **FR-005**: 시스템은 프롬프트의 업무/도메인(Task) 구분 기반의 필터링 검색 기능을 제공해야 한다.
- **FR-006**: 시스템은 이름, 태그, 업무 조건을 2개 이상 조합하여 동시에 필터링할 수 있는 다차원 검색 기능을 제공해야 한다.
- **FR-007**: 시스템은 검색 결과를 생성일시 또는 수정일시 기준으로 정렬할 수 있는 기능을 제공해야 한다.
- **FR-008**: 모든 CRUD 및 다차원 검색 API 엔드포인트는 자동화된 유닛 테스트 케이스를 통해 100% 검증되어야 한다.

### Key Entities

- **Prompt (프롬프트)**:
  - 프롬프트 자산의 메타데이터 및 식별 정보.
  - 주요 속성: 고유 식별자, 이름(Name), 설명(Description), 업무 분류(Task), 태그 목록(Tags), 생성일시, 수정일시.
  - 관계: 하나 이상의 Section(섹션)을 포함할 수 있음 (1:N 관계).

- **Section (섹션)**:
  - 프롬프트를 구성하는 하위 텍스트 블록 또는 구조화된 지침 단위.
  - 주요 속성: 고유 식별자, 섹션 이름/키(Key), 역할 또는 유형(Type), 본문 내용(Content), 표시 순서(Order), 생성일시, 수정일시.
  - 관계: 특정 Prompt에 소속됨.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 프롬프트 및 섹션의 등록, 상세 조회, 수정, 삭제(CRUD) 기능이 명세대로 작동하여 API 요청에 대해 100% 정상 응답을 보장한다.
- **SC-002**: 이름, 태그, 업무 조건을 활용한 단일 및 다차원 필터링 검색 결과의 정확도가 100% 일치한다.
- **SC-003**: 작성된 유닛 테스트 세트를 실행했을 때 모든 CRUD 및 다차원 검색 테스트 케이스가 100% 통과한다.
- **SC-004**: 일반적인 검색 요청에 대해 응답 지연 시간이 사용자 체감 속도 기준 즉각(1초 이내) 처리된다.

## Assumptions

- 프롬프트 및 섹션 API 호출 시 인증/인가 로직은 이전 단계(Day 03)에서 구축된 인증 라우팅 모듈을 준용하거나 표준 접근 통제를 따른다.
- 프롬프트에 부여되는 태그(Tag)는 문자열 형태의 목록으로 취급된다.
- 프롬프트 컴파일 및 실제 LLM 호출은 프롬프트 레지스트리 범위 외(Constitution 원칙 I 준수)이므로 포함하지 않는다.
