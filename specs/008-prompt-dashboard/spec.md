**Created**: 2026-08-03

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버전별 프롬프트 작성 및 발행 (Priority: P1)

관리자는 프롬프트 상세 화면에서 특정 버전을 선택하고 섹션·변수 정의를 작성한 뒤, 검토가 끝난 버전을 발행한다. 발행된 버전은 변경되지 않아 배포 대상의 내용이 보존된다.

**Why this priority**: 안전한 프롬프트 작성과 변경 이력 보존은 Prompt Registry의 핵심 가치다.

**Independent Test**: 초안 버전에 섹션과 변수를 추가해 발행한 후 해당 버전의 편집이 차단되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 프롬프트 상세 화면이 열린 경우, **When** 관리자가 초안 버전의 섹션 또는 변수를 저장하면, **Then** 선택한 버전에만 변경 내용이 반영된다.
2. **Given** 편집 가능한 초안 버전이 있는 경우, **When** 관리자가 발행하면, **Then** 해당 버전은 발행 상태가 되고 이후 콘텐츠, 섹션, 변수를 수정할 수 없다.
3. **Given** 발행된 버전을 선택한 경우, **When** 관리자가 상세 화면을 열면, **Then** 콘텐츠와 변수는 읽기 전용으로 표시된다.

---

### User Story 2 - 독립된 새 버전 생성 (Priority: P1)

관리자는 기존 버전을 기반으로 새 초안 버전을 생성해 다음 변경을 준비한다. 새 버전은 원본의 섹션과 변수 정의를 복사하지만 이후 서로 영향을 주지 않는다.

**Why this priority**: 이미 발행한 프롬프트를 훼손하지 않고 개선을 반복할 수 있어야 한다.

**Independent Test**: 섹션과 변수가 있는 버전에서 새 버전을 만든 뒤 새 버전의 데이터를 수정하고 원본 버전이 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 하나 이상의 버전이 있는 프롬프트가 있는 경우, **When** 관리자가 새 버전을 생성하면, **Then** 바로 이전 버전의 섹션 순서·내용과 변수 정의가 새 버전으로 복사된다.
2. **Given** 복사된 새 초안 버전이 있는 경우, **When** 관리자가 새 버전의 섹션 또는 변수를 변경하면, **Then** 모든 이전 버전의 데이터는 변경되지 않는다.
3. **Given** 프롬프트 상세 화면이 열린 경우, **When** 관리자가 사이드바에서 다른 버전을 선택하면, **Then** 선택한 버전의 독립된 섹션·변수·상태가 표시된다.

---

### User Story 3 - 배포 대상과 라벨 관리 (Priority: P1)

관리자는 발행된 버전 중 하나를 현재 운영 대상(on-live)으로 지정하고, 버전별 사용자 정의 라벨을 관리한다. SDK가 라벨을 생략해 조회해도 현재 운영 대상이 일관되게 제공된다.

**Why this priority**: 운영 애플리케이션이 사용하는 프롬프트 버전을 명확하고 안전하게 제어해야 한다.

**Independent Test**: 두 개의 발행 버전을 준비해 on-live 대상을 바꾸고, 기본 조회와 라벨 조회가 의도한 버전을 가리키는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행된 버전이 하나 이상 있는 경우, **When** 관리자가 한 버전을 on-live로 지정하면, **Then** 해당 프롬프트에서 다른 버전은 동시에 on-live가 아니다.
2. **Given** 한 버전이 on-live인 경우, **When** 관리자가 다른 발행 버전을 on-live로 지정하면, **Then** 이전 지정은 원자적으로 해제되고 새 버전만 on-live가 된다.
3. **Given** 새 버전이 생성된 경우, **When** 생성이 완료되면, **Then** `latest` 자동 라벨은 새 버전만 가리키고 이전 버전에서는 제거된다.
4. **Given** 한 프롬프트에 특정 라벨이 이미 존재하는 경우, **When** 관리자가 같은 라벨을 다른 버전에 지정하려 하면, **Then** 중복 생성 대신 기존 라벨의 대상 변경 또는 명확한 오류가 적용된다.

---

### User Story 4 - 카테고리 기반 탐색과 관리 (Priority: P2)

관리자는 카테고리를 관리하고 카테고리별로 프롬프트를 탐색한다.

**Why this priority**: 프롬프트 수가 증가해도 도메인별 관리 흐름을 유지할 수 있다.

**Independent Test**: 카테고리를 만들고 프롬프트에 연결한 뒤 해당 카테고리를 선택해 연결된 프롬프트만 확인한다.

**Acceptance Scenarios**:

1. **Given** 관리자로 로그인한 경우, **When** 카테고리를 생성, 조회, 수정 또는 삭제하면, **Then** 작업 결과가 카테고리 관리 화면에 반영된다.
2. **Given** 카테고리에 프롬프트가 연결된 경우, **When** 삭제를 시도하면, **Then** 연결 관계를 보호하는 안내를 받고 카테고리는 삭제되지 않는다.
3. **Given** 여러 카테고리와 프롬프트가 있는 경우, **When** 카테고리를 선택하면, **Then** 해당 카테고리에 속한 프롬프트만 탐색할 수 있다.

---

### User Story 5 - 서비스 진입과 안전한 대시보드 접근 (Priority: P2)

관리자는 서비스 랜딩 페이지에서 로그인 화면으로 이동하고 인증 후에만 관리 대시보드를 사용한다.

**Why this priority**: 관리 기능을 일반 방문자에게 노출하지 않으면서 서비스의 진입점을 제공한다.

**Independent Test**: 비로그인 사용자가 랜딩 페이지와 보호된 관리 URL에 각각 접근해 로그인 이동 및 접근 제어를 확인한다.

**Acceptance Scenarios**:

1. **Given** 비로그인 방문자인 경우, **When** 서비스 기본 주소에 접속하면, **Then** 서비스 소개와 로그인으로 이동할 수 있는 랜딩 페이지가 표시된다.
2. **Given** 비로그인 방문자인 경우, **When** 관리 화면 주소에 직접 접근하면, **Then** 로그인 화면으로 이동하고 관리 데이터를 볼 수 없다.
3. **Given** 관리 권한이 있는 사용자인 경우, **When** 로그인에 성공하면, **Then** 프롬프트 관리 대시보드로 이동한다.

### Edge Cases

- 발행되지 않은 초안 버전은 on-live 대상으로 지정할 수 없다.
- on-live 버전이 없는 프롬프트를 기본 라벨로 조회하면 배포 가능한 버전이 없음을 명확히 알린다.
- `latest` 또는 `production` 예약 라벨을 사용자가 임의로 생성, 삭제하거나 다른 버전에 중복 지정할 수 없다.
- 동일 버전에서 변수 이름 또는 섹션 순서가 중복되면 저장되지 않으며, 수정할 필드를 알린다.
- 다른 관리자가 같은 버전의 상태 또는 라벨을 변경한 경우, 최신 상태를 확인한 뒤 충돌을 안내하고 의도하지 않은 덮어쓰기를 막는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 인증·권한이 있는 관리자에게 PromptCategory의 생성, 조회, 수정, 삭제 기능을 제공해야 한다.
- **FR-002**: 시스템은 프롬프트마다 하나의 카테고리를 유지하고, 관리자가 카테고리별 프롬프트 목록을 탐색할 수 있게 해야 한다.
- **FR-003**: 시스템은 프롬프트 상세 화면에 해당 프롬프트의 버전 목록과 선택된 버전의 상세 정보를 함께 제공해야 한다.
- **FR-004**: 시스템은 초안 버전에서 섹션의 역할, 순서, 콘텐츠를 생성·조회·수정·삭제할 수 있게 해야 한다.
- **FR-005**: 시스템은 초안 버전에서 변수의 이름, 유형, 필수 여부, 기본값, 설명을 생성·조회·수정·삭제할 수 있게 해야 한다.
- **FR-006**: 시스템은 편집기에서 정의된 변수 참조를 일반 텍스트와 시각적으로 구분해야 한다.
- **FR-007**: 시스템은 새 버전을 생성할 때 직전 버전의 섹션과 변수 정의를 값과 관계까지 독립적으로 복사해야 한다.
- **FR-008**: 시스템은 새 버전 생성 후 어느 버전의 섹션·변수·콘텐츠를 변경해도 다른 버전의 데이터를 변경하지 않아야 한다.
- **FR-009**: 시스템은 초안 버전을 발행할 수 있게 해야 하며, 발행 후 해당 버전의 콘텐츠, 섹션, 변수 정의를 변경할 수 없게 해야 한다.
- **FR-010**: 시스템은 발행된 버전만 on-live로 지정할 수 있게 해야 하며, 하나의 프롬프트에서 on-live 버전은 최대 하나여야 한다.
- **FR-011**: 시스템은 on-live 지정을 기존 기본 조회 라벨인 `production` 예약 라벨과 일대일로 연계해야 한다. 라벨이 생략된 SDK 조회는 `production`이 가리키는 on-live 버전을 반환해야 한다.
- **FR-012**: 시스템은 새 버전 생성 시 `latest` 예약 라벨을 새 버전에 자동 지정하고, 같은 프롬프트의 이전 버전에서 `latest`를 자동 제거해야 한다.
- **FR-013**: 시스템은 버전에 사용자 정의 라벨을 생성, 변경, 제거할 수 있게 해야 하며, 동일 프롬프트 내에서 같은 라벨 이름은 하나의 버전만 가리키게 해야 한다.
- **FR-014**: 시스템은 `latest`와 `production`을 시스템 관리 예약 라벨로 취급하고, 사용자 정의 라벨 작업으로 이 정책을 우회할 수 없게 해야 한다.
- **FR-015**: 시스템은 서비스 랜딩 페이지와 로그인 진입점을 제공해야 한다.
- **FR-016**: 시스템은 인증되지 않았거나 관리 권한이 없는 사용자가 대시보드의 프롬프트, 버전, 카테고리, 라벨 관리 기능에 접근할 수 없게 해야 한다.
- **FR-017**: 시스템은 외부 SDK에 프롬프트·버전·카테고리·라벨의 생성, 수정, 삭제 기능 또는 LLM 실행 기능을 노출하지 않아야 한다.
- **FR-018**: 시스템은 기본 조회 라벨이 가리키는 버전이 없는 경우, 다른 라벨이나 초안으로 자동 대체하지 않아야 한다.

### Key Entities

- **PromptCategory**: 프롬프트 자산을 분류하는 도메인 범주이며 여러 프롬프트와 연결된다.
- **Prompt**: 이름, 설명, 카테고리와 버전 이력을 가지는 최상위 프롬프트 자산이다.
- **Version**: 특정 시점의 프롬프트 콘텐츠, 섹션, 변수 정의를 독립적으로 보유하는 버전이다. 초안 또는 발행 상태를 가진다.
- **Section**: 버전 안에서 순서와 역할을 가지는 프롬프트 콘텐츠 단위다.
- **VariableDefinition**: 버전에서 사용 가능한 동적 변수의 이름, 유형, 검증 정보를 나타낸다.
- **Label**: 한 프롬프트 안에서 특정 버전을 가리키는 고유한 이름표다. `production`과 `latest`는 시스템 예약 라벨이다.
- **On-live designation**: 현재 외부 기본 조회에 제공되는 발행 버전을 나타내는 단일 운영 상태이며 `production` 라벨로 표현된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 새 프롬프트를 만들고 섹션과 변수 정의를 추가한 초안 버전을 발행하기까지 5분 이내에 완료할 수 있다.
- **SC-002**: 새 버전 생성 후 복사된 섹션과 변수 정의가 원본 버전과 독립적임을 모든 버전 관리 수용 시나리오에서 확인할 수 있다.
- **SC-003**: on-live 지정 변경 뒤 기본 조회는 항상 하나의 발행 버전만 반환하며 초안 버전을 반환하지 않는다.
- **SC-004**: 새 버전 생성이 완료된 모든 경우에 `latest`는 정확히 하나의 최신 버전만 가리킨다.
- **SC-005**: 보호된 관리 화면 접근 시도는 인증되지 않은 사용자에게 관리 데이터를 노출하지 않는다.
- **SC-006**: 관리자는 카테고리 선택 후 해당 카테고리에 연결된 프롬프트를 한 화면에서 식별할 수 있다.

## Assumptions

- 대시보드 사용자는 기존 사용자 계정 중 관리 권한을 가진 사용자로 한정한다.
- 발행은 콘텐츠 불변성을 확정하는 상태이며, on-live 지정은 발행된 버전 중 배포 대상을 선택하는 별도 작업이다.
- `production`은 기존 SDK 기본 조회 호환성을 위해 on-live 버전을 가리키는 시스템 예약 라벨로 유지한다.
- `latest`는 생성 시점이 가장 최근인 버전을 가리키는 시스템 예약 라벨이며 발행 여부와 무관하게 자동 갱신된다.
- 사용자 정의 라벨은 영문·숫자·하이픈 식별자로 제한하며 예약 라벨 이름은 사용할 수 없다.
- 랜딩 페이지는 공개 정보와 로그인 진입만 제공하며 회원 가입·비밀번호 재설정·외부 인증 연동은 이번 범위에 포함하지 않는다.
- 문서 반영 시 `docs/prompt-server-requirements.md`에는 대시보드·상태·라벨 정책을, `docs/project-spec.md`와 `docs/architecture.md`에는 `production`/on-live/`latest` 정합성을 반영한다. `docs/project_plan.md`에는 Day 08 이후 대시보드 고도화 일정을 우선 배치하고 이후 SDK 및 통합 일정을 순연한다.
