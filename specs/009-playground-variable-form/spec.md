## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프롬프트별 변수 입력 준비 (Priority: P1)

관리자는 특정 프롬프트 버전을 Playground에서 선택해, 그 버전에 정의된 동적 변수와 각 변수의 설명·필수 여부·기본값을 한 화면에서 확인하고 값을 입력한다. 이 단계는 실행 전 입력값을 준비하는 데만 사용된다.

**Why this priority**: 동적 변수를 올바르게 채우는 것은 향후 프롬프트 검토와 실행의 전제이며, 값 입력만으로도 관리자는 필요한 정보를 빠짐없이 파악할 수 있다.

**Independent Test**: 변수가 정의된 프롬프트 버전을 열어 모든 변수가 입력 폼에 표시되고, 각 입력값을 변경할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 관리자가 접근 권한을 갖고 변수가 정의된 프롬프트 버전을 선택한 경우, **When** Playground를 열면, **Then** 해당 버전의 변수마다 이름, 설명, 유형, 필수 여부, 기본값 및 값을 입력할 수 있는 항목이 표시된다.
2. **Given** 필수 변수와 선택 변수가 함께 정의된 경우, **When** 관리자가 Playground를 확인하면, **Then** 필수 여부를 구분할 수 있고 선택 변수에는 정의된 기본값이 있으면 초기 값으로 제시된다.
3. **Given** 관리자가 하나 이상의 변수 값을 입력한 경우, **When** 화면 내 다른 Playground 영역을 확인하면, **Then** 현재 입력값은 화면에 유지되고 값의 이름 및 대상 버전을 식별할 수 있다.

---

### User Story 2 - 변수 유형에 맞는 입력 (Priority: P1)

관리자는 변수 유형에 맞는 방식으로 값을 입력하고, 잘못된 형식의 값은 즉시 이해할 수 있는 안내를 받는다.

**Why this priority**: 변수 입력 오류를 실행 이후에 발견하지 않도록 하여 프롬프트 검토의 신뢰성과 효율을 높인다.

**Independent Test**: 문자열, 숫자, 불리언, 구조화된 데이터 유형을 각각 가진 변수를 열어 유효한 값을 입력하고, 유형에 맞지 않는 값을 입력했을 때 안내되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 문자열 또는 숫자 유형의 변수가 있는 경우, **When** 관리자가 값을 입력하면, **Then** 해당 유형에 맞는 값만 유효한 것으로 표시된다.
2. **Given** 불리언 유형의 변수가 있는 경우, **When** 관리자가 값을 선택하면, **Then** 참 또는 거짓 중 하나를 명확히 선택할 수 있다.
3. **Given** 구조화된 데이터 유형의 변수가 있는 경우, **When** 관리자가 형식에 맞지 않는 값을 입력하면, **Then** 해당 변수 옆에 수정 방법을 알 수 있는 오류 안내가 표시된다.
4. **Given** 필수 변수를 비워 둔 경우, **When** 관리자가 입력 상태를 검토하면, **Then** 누락된 필수 변수를 식별할 수 있다.

---

### User Story 3 - 비어 있는 변수 세트 이해 (Priority: P2)

관리자는 선택한 프롬프트 버전에 동적 변수가 없을 때도 Playground의 목적과 현재 상태를 이해한다.

**Why this priority**: 변수 없는 프롬프트에서도 빈 화면이나 오류로 오인하지 않고, 향후 Playground 확장과 일관된 탐색 흐름을 유지할 수 있다.

**Independent Test**: 변수 정의가 없는 프롬프트 버전을 열어 입력 항목 대신 변수 없음 상태와 기본 Playground 레이아웃이 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 선택한 프롬프트 버전에 변수가 없는 경우, **When** 관리자가 Playground를 열면, **Then** 변수 입력이 필요 없음을 명확히 알리는 상태가 표시된다.
2. **Given** 관리자가 존재하지 않거나 접근할 수 없는 프롬프트 버전으로 Playground에 접근하는 경우, **When** 정보를 불러오려 하면, **Then** 다른 프롬프트의 변수 정보는 노출되지 않고 이해 가능한 오류 또는 접근 안내가 표시된다.

### Edge Cases

- 선택한 프롬프트 버전에 변수가 없으면 빈 입력 폼 대신 변수 없음 상태를 표시한다.
- 기본값이 없는 선택 변수는 비어 있는 입력 상태로 표시한다.
- 필수 변수에 기본값이 있더라도 관리자는 해당 값을 확인하고 필요 시 변경할 수 있다.
- 변수 정의가 유효하지 않거나 읽을 수 없으면 부분적으로 잘못된 입력 폼을 표시하지 않고 오류를 안내한다.
- 입력 중 화면을 새로 고치거나 다른 버전으로 이동하면, 이번 범위에서는 입력값의 복원이나 저장을 보장하지 않는다.
- Playground는 입력 준비만 제공하며, 입력값을 사용한 프롬프트 컴파일·미리 보기·LLM 호출은 제공하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 인증·권한이 있는 관리자만 Playground 및 선택한 프롬프트 버전의 변수 스키마에 접근할 수 있게 해야 한다.
- **FR-002**: 시스템은 권한이 있는 관리자가 선택한 초안 또는 발행 프롬프트 버전의 변수 스키마를 조회할 수 있게 해야 하며, 각 항목에 이름, 유형, 필수 여부, 설명 및 기본값을 제공해야 한다.
- **FR-003**: 시스템은 선택한 프롬프트 버전의 변수 정의만 제공해야 하며, 다른 프롬프트 또는 버전의 변수 정보를 함께 반환하거나 표시하지 않아야 한다.
- **FR-004**: 시스템은 프롬프트 버전 상세 화면에서 선택된 버전으로 Playground에 진입하게 해야 하며, 기본 화면에 해당 프롬프트 및 버전의 식별 정보, 변수 입력 영역, 입력 상태 안내 영역을 제공해야 한다.
- **FR-005**: 시스템은 `string`, `number`, `boolean`, `json` 유형별로 관리자가 값을 입력하거나 선택할 수 있는 적절한 입력 항목을 제공해야 한다.
- **FR-006**: 시스템은 입력값이 해당 변수 유형과 일치하는지 검증하고, 불일치한 값에는 변수별로 이해 가능한 오류를 표시해야 한다.
- **FR-007**: 시스템은 필수 여부와 기본값을 반영하여 입력 폼의 초기 상태를 구성해야 한다. 기본값이 있는 변수는 기본값을 초기 값으로 표시하고, 필수이면서 값이 없는 변수는 누락 상태를 식별할 수 있게 해야 한다.
- **FR-008**: 시스템은 변수가 없는 프롬프트 버전에 대해 오류가 아닌 변수 없음 상태를 표시해야 한다.
- **FR-009**: 시스템은 존재하지 않는 프롬프트 버전 또는 접근 권한이 없는 요청에 대해 변수 스키마를 노출하지 않고 적절한 오류 또는 접근 안내를 제공해야 한다.
- **FR-010**: 시스템은 Playground에서 입력한 값을 서버에 영구 저장하지 않아야 한다.
- **FR-011**: 시스템은 이번 기능 범위에서 입력값을 사용한 프롬프트 컴파일, 렌더링 결과 미리 보기, LLM 호출 또는 외부 SDK 실행 기능을 제공하지 않아야 한다.

### Key Entities

- **Playground Session**: 관리자가 특정 프롬프트 버전을 확인하며 임시로 변수 값을 입력하는 화면 단위의 작업 상태다. 이번 범위에서는 영구 저장되지 않는다.
- **Variable Schema**: 선택한 프롬프트 버전에 정의된 동적 변수의 이름, 유형, 필수 여부, 설명 및 기본값으로 구성된 조회 정보다.
- **Variable Input**: 관리자가 Playground에서 특정 Variable Schema에 대해 입력한 임시 값과 유효성 상태다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 변수가 정의된 프롬프트 버전을 선택한 관리자는 1분 이내에 모든 변수의 이름, 유형, 필수 여부 및 기본값을 확인하고 값을 입력할 수 있다.
- **SC-002**: 지원되는 네 가지 변수 유형의 유효·무효 입력 사례에서 각 입력 항목은 값의 유효성 또는 수정 안내를 일관되게 표시한다.
- **SC-003**: 변수 없는 프롬프트 버전을 연 모든 관리자는 오류 화면 대신 변수 입력이 필요 없다는 상태를 확인할 수 있다.
- **SC-004**: 권한이 없는 사용자 또는 존재하지 않는 버전에 대한 모든 변수 스키마 조회 시도는 다른 프롬프트 버전의 변수 정보를 노출하지 않는다.
- **SC-005**: 이 기능의 수용 시나리오 전체에서 프롬프트 컴파일, 결과 미리 보기 또는 LLM 호출이 발생하지 않는다.

## Assumptions

- Playground는 기존 대시보드에 인증된 관리자가 접근하는 화면으로 제공된다.
- 권한이 있는 관리자는 초안과 발행 버전 모두에서 Playground의 변수 입력 준비 화면을 사용할 수 있다.
- Playground는 독립적인 프롬프트·버전 선택 화면을 제공하지 않고, 프롬프트 버전 상세 화면에서 선택된 버전으로만 진입한다.
- 변수 정의는 기존 프롬프트 버전 관리 기능에서 이미 관리되며, 이번 기능은 그 정의를 읽기 전용으로 사용한다.
- 지원 변수 유형은 기존 대시보드 정책과 동일하게 `string`, `number`, `boolean`, `json` 네 가지로 제한한다.
- 입력값은 브라우저 화면에 임시로만 유지하며, 새로 고침·이동·재접속 후 복원되지 않는다.
- 실제 프롬프트 컴파일, 렌더링 결과 미리 보기, LLM 호출 및 입력값의 공유·저장은 후속 기능 범위다.
