## Clarifications

### Session 2026-08-18

- Q: Playground 미리보기의 컴파일은 어디에서 실행해야 하는가? → A: Django 서버가 Playground 제출을 받아 SDK `compile()`을 실행하고 결과 HTML을 반환한다.
- Q: Gemini live E2E 호출을 어떻게 보호해야 하는가? → A: 명시적인 live 실행 플래그가 있을 때만 Gemini를 정확히 1회 호출한다.
- Q: Gemini client 의존성은 어느 범위에 두어야 하는가? → A: E2E 예제 전용 의존성으로만 선언하고 core SDK에서는 제외한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Playground에서 컴파일 결과 미리보기 (Priority: P1)

인증된 관리자는 특정 프롬프트 버전의 Playground에서 동적 변수 값을 입력하고, 외부 LLM에 내용을 전송하지 않은 채 최종 컴파일 텍스트를 확인한다.

**Why this priority**: 실제 비용이나 외부 데이터 전송 없이 프롬프트와 변수 조합을 검토하는 것이 Playground 완성의 핵심 가치다.

**Independent Test**: 동적 변수가 있는 프롬프트 버전을 열고 유효한 값을 입력해 미리보기를 요청한 뒤, 모든 자리표시자가 치환된 결과와 원본 식별 정보가 표시되고 외부 LLM 요청이 없었는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 관리자가 접근 가능한 프롬프트 버전과 유효한 변수 값을 준비한 경우, **When** Playground 폼을 제출해 컴파일 미리보기를 요청하면, **Then** Django 서버가 SDK `compile()`로 선택한 버전의 모든 섹션과 집계 텍스트를 치환하고 원본 프롬프트 식별 정보와 함께 결과 HTML로 반환한다.
2. **Given** 선택한 프롬프트 버전에 변수가 없는 경우, **When** 관리자가 컴파일 미리보기를 요청하면, **Then** 원문과 동일한 컴파일 결과가 표시된다.
3. **Given** 미리보기가 성공한 경우, **When** 관리자가 결과를 검토하면, **Then** 어떤 LLM 공급자에도 요청이 전송되지 않았고 LLM 응답·토큰·비용 정보가 생성되지 않았음을 명확히 알 수 있다.

---

### User Story 2 - 컴파일 오류를 안전하게 수정 (Priority: P1)

관리자는 누락되거나 잘못된 변수 값을 제출했을 때 원인을 확인하고 기존 입력을 유지한 채 수정할 수 있으며, 불완전한 컴파일 텍스트는 결과로 오인되지 않는다.

**Why this priority**: 실패 결과를 안전하게 다루지 않으면 검토자가 미완성 프롬프트를 정상 결과로 판단하거나 민감한 입력이 오류 메시지에 노출될 수 있다.

**Independent Test**: 필수값 누락, 잘못된 유형, 선언되지 않은 값, 템플릿 불일치 사례를 각각 제출하여 오류 위치와 이유가 표시되고 부분 컴파일 결과 및 입력 원문이 오류·로그에 노출되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필수 변수가 누락되거나 값의 유형이 잘못된 경우, **When** 미리보기를 요청하면, **Then** 영향받은 변수와 수정 가능한 이유가 표시되고 컴파일 결과는 표시되지 않는다.
2. **Given** 템플릿과 변수 선언이 일치하지 않는 경우, **When** 미리보기를 요청하면, **Then** 템플릿 정의 오류가 안내되고 부분적으로 치환된 텍스트는 표시되지 않는다.
3. **Given** 컴파일이 실패한 경우, **When** 관리자가 폼으로 돌아오면, **Then** 안전하게 다시 표시할 수 있는 입력 상태는 유지되어 즉시 수정할 수 있다.

---

### User Story 3 - 실제 Gemini 호출까지 이어지는 예제 실행 (Priority: P2)

애플리케이션 개발자는 저장소의 단일 E2E 예제를 따라 실행하여, 이미 발행된 프롬프트를 실제 Prompt Server에서 SDK로 조회하고 로컬에서 컴파일한 다음 Gemini용 호출 인자로 변환해 실제 Gemini 응답을 확인한다.

**Why this priority**: 분리되어 개발된 registry, SDK retrieval, compilation, provider conversion이 실제 소비자 흐름에서 함께 작동함을 보여주고 채택자가 자신의 서비스에 적용할 기준을 제공한다.

**Independent Test**: 문서화된 사전 조건과 환경 설정만 준비한 새 사용자가 예제를 한 번 실행해 서버 조회 대상 식별 정보, 컴파일 완료 확인, Gemini 응답을 순서대로 확인한다.

**Acceptance Scenarios**:

1. **Given** 실행 중인 실제 Prompt Server, 유효한 read-only SDK API key, 발행되어 on-live로 지정된 예제 프롬프트, 유효한 Gemini 자격 증명이 있는 경우, **When** 개발자가 명시적인 live 실행 플래그와 함께 E2E 예제를 실행하면, **Then** 예제는 프롬프트 조회, 로컬 컴파일, Gemini 인자 변환, 정확히 한 번의 실제 Gemini 호출을 순서대로 완료하고 응답을 표시한다.
2. **Given** 필요한 서버 주소·프롬프트 식별자·변수 값·모델 설정이 문서화된 방식으로 제공된 경우, **When** 예제를 검토하면, **Then** 비밀값을 소스에 기록하지 않고 각 단계의 애플리케이션 책임 경계를 식별할 수 있다.
3. **Given** Prompt Server 조회나 Gemini 호출이 실패한 경우, **When** 예제가 종료되면, **Then** 실패 단계를 구분하는 실행 가능한 안내를 제공하고 자격 증명이나 전체 프롬프트 내용을 오류에 노출하지 않는다.

### Edge Cases

- Playground에서 동일 변수가 여러 섹션에 반복되면 모든 위치에 동일한 검증 완료 값이 반영된다.
- 입력값 자체에 자리표시자와 유사한 문자열이 있어도 두 번째 템플릿 치환 대상으로 해석하지 않는다.
- 컴파일 결과가 빈 문자열이거나 공백·줄바꿈·Unicode를 포함하면 성공 여부를 혼동하지 않도록 상태를 구분하고 원문 형식을 보존한다.
- 관리자가 미리보기 요청 사이에 접근 권한을 잃거나 대상 버전이 삭제되면 다른 버전으로 대체하지 않고 접근 실패를 안내한다.
- 빠른 연속 제출이나 페이지 재제출이 발생해도 외부 LLM 호출은 발생하지 않으며 입력값과 결과는 영구 저장되지 않는다.
- E2E 예제의 대상 프롬프트에 on-live 버전이 없거나 요청한 식별자가 없으면 초안, latest 또는 다른 라벨로 대체하지 않고 registry 단계에서 중단한다.
- Prompt Server가 도달 불가능하거나 인증을 거부하거나 잘못된 응답을 반환하면 Gemini 호출 단계로 진행하지 않는다.
- Gemini 자격 증명, 모델 접근 권한, 할당량 또는 네트워크 문제로 호출이 실패하면 registry 조회·컴파일 실패와 구분해 안내한다.
- Gemini가 빈 응답이나 예상 밖의 응답 형태를 반환하면 성공 텍스트로 오인하지 않고 공급자 응답 오류로 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Playground는 인증·권한이 있는 관리자만 선택한 프롬프트 버전의 컴파일 미리보기를 요청할 수 있게 해야 한다.
- **FR-002**: Playground는 선택한 초안 또는 발행 버전의 기존 변수 입력 폼을 사용하여 컴파일 미리보기를 제공해야 하며, 별도의 프롬프트·버전 선택 흐름을 추가하지 않아야 한다.
- **FR-003**: Django 서버는 Playground 폼 제출을 받아 프로젝트의 공개 SDK `compile()` 계약으로 미리보기를 컴파일하고 결과 HTML을 반환해야 하며, 브라우저에 별도의 컴파일 엔진을 구현하거나 별도 내부 컴파일 API를 추가하지 않아야 한다.
- **FR-003a**: 미리보기는 SDK `compile()` 계약과 동일한 변수 기본값, 필수 여부, 유형 검증, 선언되지 않은 입력 거부 및 템플릿 검증 규칙을 적용해야 한다.
- **FR-004**: 컴파일 성공 결과는 원본 프롬프트와 버전을 식별할 수 있는 정보, 순서가 보존된 역할별 섹션 텍스트, 전체 집계 텍스트를 제공해야 한다.
- **FR-005**: 미리보기는 선택한 프롬프트 버전의 내용을 로컬에서만 컴파일해야 하며, LLM 공급자 호출, 모델 선택, 토큰 계산, 비용 추정 또는 LLM 응답 생성을 수행하지 않아야 한다.
- **FR-006**: 컴파일 실패 시 영향받은 변수 또는 템플릿 문제와 수정 이유를 안내하고, 부분 컴파일 결과를 반환하거나 표시하지 않아야 한다.
- **FR-007**: 미리보기 오류, 표현 및 로그는 관리자가 입력한 변수 값이나 컴파일된 프롬프트 전체를 노출하지 않아야 한다.
- **FR-008**: Playground의 입력값과 컴파일 결과는 영구 저장되지 않아야 하며 프롬프트 원본 또는 버전 상태를 변경하지 않아야 한다.
- **FR-009**: 미리보기 결과와 오류 상태는 빈 결과, 공백, 줄바꿈 및 Unicode를 명확하고 원형 그대로 표시할 수 있어야 한다.
- **FR-010**: 저장소는 실제 Prompt Server 조회에서 실제 Gemini 응답까지의 전체 소비자 여정을 보여주는 하나의 실행 가능한 E2E 예제를 제공해야 한다.
- **FR-011**: E2E 예제는 read-only SDK를 사용해 지정된 프롬프트를 조회하고, 해당 SDK의 로컬 컴파일 계약으로 변수를 적용하며, 완성된 결과를 Gemini 호출 인자로 변환한 뒤 애플리케이션 소유 Gemini client로 실제 호출해야 한다.
- **FR-012**: E2E 예제는 SDK 또는 Prompt Server에 LLM 실행 책임을 추가하지 않아야 하며, 프롬프트 생성·수정·삭제·발행·라벨 변경을 수행하지 않아야 한다.
- **FR-013**: E2E 예제는 실행 전 필요한 Prompt Server 상태, 발행 및 on-live 지정된 예제 프롬프트 계약, 서버 주소, 프롬프트 식별자, 변수 입력, SDK API key, Gemini 자격 증명, 모델 설정 및 실행 명령을 한 흐름으로 문서화해야 한다.
- **FR-014**: 모든 자격 증명과 환경별 주소·모델 값은 실행 시 외부 설정으로 제공되어야 하고, 실제 비밀값은 예제 코드·문서·기본값·출력·오류·로그에 포함되지 않아야 한다.
- **FR-014a**: 실제 Gemini client 의존성은 E2E 예제 전용 범위에만 선언해야 하며, core SDK의 기본 runtime 의존성이나 선택적 provider extra에 추가하지 않아야 한다.
- **FR-015**: E2E 예제는 registry 조회, 로컬 컴파일, 공급자 인자 변환, Gemini 호출 및 응답 확인 단계를 식별 가능하게 구분하고, 선행 단계 실패 시 후속 외부 호출을 수행하지 않아야 한다.
- **FR-015a**: E2E 예제는 명시적인 live 실행 플래그가 제공된 경우에만 실제 Gemini 요청을 정확히 한 번 수행해야 하며, 플래그가 없으면 Gemini 요청을 0건으로 유지한 채 live 실행 방법을 안내하고 종료해야 한다.
- **FR-016**: E2E 예제는 성공 시 조회된 프롬프트의 안전한 식별 정보와 단계별 완료 상태 및 Gemini 응답을 보여주되, API key와 기타 비밀값을 출력하지 않아야 한다.
- **FR-017**: E2E 예제는 잘못된 설정, registry 통신·인증·대상 없음·배포 가능 버전 없음, 컴파일 검증, Gemini 인증·할당량·통신·응답 실패를 단계별로 구분하는 실행 가능한 오류를 제공해야 한다.
- **FR-018**: Playground 미리보기의 성공·검증 실패·권한·비영구성·무외부호출 계약과 E2E 예제의 외부 경계를 반복 가능한 자동 검증으로 보호해야 하며, 기본 자동 검증은 실제 Gemini 비용이나 자격 증명을 요구하지 않아야 한다.

### Key Entities

- **Playground compilation request**: 특정 프롬프트 버전과 관리자가 임시 입력한 변수 값으로 구성되며 영구 저장되지 않는 미리보기 요청이다.
- **Compiled preview**: 원본 프롬프트 식별 정보, 순서가 보존된 역할별 텍스트, 집계 텍스트를 포함하는 로컬 컴파일 성공 결과다.
- **E2E example configuration**: 실제 registry와 Gemini에 연결하기 위해 실행자가 외부에서 제공하는 서버 주소, 프롬프트 식별자, 변수 값, 모델 설정 및 비밀 자격 증명의 참조다.
- **E2E execution**: registry retrieval, local compilation, provider conversion, Gemini invocation, response 확인으로 이어지는 단계별 소비자 여정이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 유효한 값이 제공된 Playground 수용 사례의 100%에서 관리자는 2초 이내에 모든 역할별 섹션과 전체 컴파일 텍스트를 확인하며 외부 LLM 요청은 0건이다.
- **SC-002**: 누락값, 잘못된 유형, 선언되지 않은 값 및 템플릿 불일치 사례의 100%에서 부분 컴파일 결과 없이 영향받은 항목과 수정 이유가 표시된다.
- **SC-003**: Playground 미리보기 성공·실패 사례의 100%에서 입력값과 컴파일 결과의 영구 저장 건수, LLM 호출 건수, 프롬프트 원본 변경 건수는 모두 0건이다.
- **SC-004**: 문서화된 사전 조건을 갖춘 개발자는 하나의 예제 실행으로 Prompt Server 조회, 로컬 컴파일, Gemini 변환, 실제 Gemini 응답 확인의 네 단계를 10분 이내에 완료할 수 있다.
- **SC-005**: E2E 예제의 필수 설정 및 주요 실패 단계 점검 사례의 100%가 실패 원인을 registry, compilation 또는 Gemini 단계로 구분하며 비밀값 노출은 0건이다.
- **SC-006**: 기본 자동 검증과 live 실행 플래그가 없는 모든 예제 실행은 실제 Gemini 요청을 0건으로 유지하며, 명시적인 live 실행 플래그가 있는 E2E 실행만 외부 Gemini 요청을 정확히 1건 수행한다.

## Assumptions

- Playground 사용자는 기존 대시보드의 인증된 관리자이며, Day 09에서 정의한 특정 버전 상세 화면 진입과 임시 변수 입력 흐름을 그대로 사용한다.
- Playground는 관리자가 접근 가능한 초안과 발행 버전을 미리볼 수 있지만, 프롬프트 내용이나 상태를 변경하지 않는다.
- 미리보기는 기존 SDK의 `CompiledPrompt` 계약을 재사용하며 새로운 템플릿 문법이나 변수 유형을 추가하지 않는다.
- E2E 예제는 기존 read-only Prompt Server API, SDK retrieval·compile 기능, Gemini adapter 계약이 이미 사용 가능함을 전제로 한다.
- Gemini client 패키지는 live E2E 예제를 실행하는 소비자 코드의 전용 의존성이며 core SDK의 설치 계약에는 포함되지 않는다.
- E2E 실행자는 대시보드에서 예제 프롬프트를 미리 생성·발행하고 on-live로 지정하며, 예제 자체는 공유 또는 운영 registry 데이터를 변경하지 않는다.
- 실제 Gemini 호출은 명시적으로 live 예제를 실행한 개발자 애플리케이션의 책임이며 비용, 할당량, 모델 접근 권한 및 응답 사용도 실행자가 관리한다.
- E2E 예제의 기본 경로는 텍스트 프롬프트와 단일 Gemini 응답 확인까지이며 streaming, multimodal input, tool call, retry, tracing, evaluation 및 비용 분석은 범위 밖이다.
- 자동 검증은 외부 경계를 대체 가능한 test double로 확인하고, live E2E 실행은 사용자가 별도로 준비한 실제 서비스와 자격 증명으로 수행한다.
